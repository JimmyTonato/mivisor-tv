# MiVisor TV · Entrega 4s: revisión de arquitectura A1–A11

La 4r está en `docs/entregas/4r.md`. Se mantiene todo. Esta entrega responde a la revisión «MiVisor APK · Revisión de
arquitectura» (contraste con McP2P 1.5.8). Se separa siempre **lo que dice el código** de **lo observado**: no se han
hecho pruebas en dispositivo desde aquí. Las pruebas de la tabla son las que ya existen o las que corre CI.

## Cambios de esta entrega

| Cambio | Dónde | Comprobación mínima |
| --- | --- | --- |
| **Parche 0014.** Corrige el defecto del 0004: al quitar trackers repetidos se pasaba toda la URL a minúsculas y se quitaba la barra final, así que dos trackers con token o ruta distintos (`/announce/AbC` y `/announce/abc`) se tomaban por el mismo y uno se perdía. Ahora solo se normalizan el esquema y el host. La ruta, la consulta y el fragmento se respetan; la barra final solo se quita si no hay consulta ni fragmento | `ace-wire/src/transport.rs` · `tracker_dedup_key`, `normalize_trackers` | Prueba `mivisor_trackers_tokens_y_rutas_distintos_no_se_pierden` (CI). Cadena 0001–0014 aplicada desde cero: idéntica |

| **Respaldo de decodificador (A2).** Si el decodificador por hardware falla al iniciarse, Media3 prueba el siguiente en vez de dar error.   no a la app.
